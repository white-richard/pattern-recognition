\section{Theory}
\label{sec:theory}

\subsection{Support Vector Machines}
Support Vector Machines (SVM) are a class of classifiers that find the optimal hyperplane
that maximizes the margin between two classes in a high-dimensional feature space. Given
a set of training images $$\mathcal{D} = \{(x_i, y_i)\}_{i=1}^N$$ where $x_i \in \mathbb{R}^d$
are the feature vectors and $y_i \in \{-1, 1\}$ are the class labels. The SVM optimization problem
can be formulated as:
\begin{align*}
	\min_{w, b, \xi} \quad  & \frac{1}{2} \|w\|^2 + C \sum_{i=1}^N \xi_i                             \\
	\text{subject to} \quad & y_i (w^T \phi(x_i) + b) \geq 1 - \xi_i, \quad \xi_i \geq 0, \quad i=1,
	\ldots, N
\end{align*}
where $w$ and $b$ are the weight and bias of the hyperplane, $\xi_i$ are slack variables that
allow for misclassification, $C$ is a regularization parameter that controls the trade-off
between maximizing the margin and minimizing the classification error, and $\phi(x)$ is a feature
mapping function that transforms the input data into a higher-dimensional space where it may be
linearly separable.

This is formally known as the soft-margin SVM formulation, which allows for some misclassification
in the training data to allow for better generalization to unseen data. It is commonly
reformulated as a contrained optimization problem which can can solved using Lagrange multipliers
and the kernel trick, which allows for efficient computation of the inner products in the
high-dimensional feature space without explicitly computing the mapping $\phi(x)$. The
discriminate can be expressed as:
\begin{equation*}
	f(x) = \sum_{i=1}^N \alpha_i y_i K(x_i, x) + b
\end{equation*}
where $\alpha_i$ are the Lagrange multipliers and $K(x_i, x)$ is the kernel function that
computes the inner product in the feature space. Two common kernel functions include the
polynomial kernel $K(x_i, x) = (x_i^T x + 1)^D$ and the RBF kernel
$K(x_i, x) = \exp(-\gamma \|x_i - x\|^2)$,
where $D$ is the degree of the polynomial and $\gamma$ is a parameter that controls the width
of the RBF kernel. The most influential training samples to the decision boundary are known as
the support vectors, which correspond to the non-zero $\alpha_i$ in the solution. In the case
of a linear classifier, the kernel function is the dot product $K(x_i, x) = x_i^T x$, and the
decision boundary is a linear hyperplane in the original feature space. However, data is not
always linearly separable or yields the best performance with a soft-marin SVM. It is instead
desirable to use a non-linear kernel such as the polynomial or RBF kernel, which can transform
the data into higher-dimensional space which is hopefully linearly separable. This
mapping function looks like:
\begin{equation*}
	\phi: \mathbb{R}^d \rightarrow \mathbb{R}^D, \quad D >> d
\end{equation*}
and the hyperplane is found in $D$.

Data can exist at different scales which can cause features with larger scales to
dominate the decision boundary. It is crucial to perform feature scaling before applying SVMs to
ensure that all features contribute equally. One common approach is to scale all values with
the range of $[-1, 1]$. This can be achieved by the following:
\begin{equation*}
	x' = \frac{x - \min(x)}{\max(x) - \min(x)} \times (max(x) - \min(x)) + \min(x)
\end{equation*}
so the smallest value in a feature is mapped to -1 and the largest value is mapped to 1.

\subsection{Model Selection via Validation}
Model selection is the process of selecting the best model from a set of candidate models based
on their performance on a validation set. The validation set is a subset of the training data
that is not used for training the model, but rather for evaluating its performance and tuning
hyperparameters. The goal of model selection is to find the model that generalizes best to
unseen data, which is typically measured by its performance on a separate test set.

This process can be done in a systematic way by performing a grid search over a range of
hyperparameters and evaluating the performance of each model on the validation set.
The hyperparameters that yield the best validation performance are then selected for the
final model.

\subsection{PCA as a Feature Extractor}
Principal Component Analysis (PCA) is a dimensionality reduction technique that is
used extract features from high-dimensional image data. PCA has been covered in a
previous assignment, so specific theory is omitted as well. However, it is worth noting
the common practice of using only the top $k$ eigenvectors as features. This is because the
eigenvalues associated with the eigenvectors represent the amount of variance captured by each
eigenvector, and the top $k$ eigenvectors capture the most variance in the data. By using only
the top $k$ eigenvectors, we can reduce the dimensionality of the data from 320 (16x20 pixels)
or 2880 (48x60 pixels) features. By reducing the dimensionality, the curse of dimensionality
is mitigated while still being expressive enough to capture relevant information for
classification.

The experiments were conducted with a gender dataset containing 400 images from 400 people
with equal representation between males and females. Two image resolutions are used: 16x20
and 48x60 pixels. The dataset is split into a training, validation, and testing
sets and evaluated using a three-fold cross-validation. The top 30 eigenvectors are used
as features for both SVMs and the Bayes classifier.

\subsection{Experiments 1 \& 2}

In this set of experiments, we compare the performance of SVMs and Bayes classifier. The SVM is
implemented with a polynomial and RBF kernel. The Bayes classifier is implemented with a Gaussian
distribution and parameters are estimated using ML estimation on the training data and Mahalanobis
distance for classification. Equal priors $P(\omega_1) = P(\omega_2)$ are assumed in the
calculations since the dataset is balanced. In order to fairly compare between SVMs and Bayes,
the same eigen-cofficients are used between the two classifiers.

\paragraph{SVM.}
After performing the sweep, the best parameters for the polynomial kernel were found to be $C=0.1$ and $D=1$ for both resolutions except for the 48x60
resolution where $D=3$ performed best.
For the RBF kernel, the best parameters for each resolution were found to have one fold with $C=1$ and $\gamma=0.1$ and two folds with $C=10$ and $\gamma=0.1$.
The best parameters for each fold and resolution are shown in Tables \ref{tab:svm_bayes_16x20} and \ref{tab:svm_bayes_48x60}.
It's notable that RBF kernels generally performed better than polynomial kernels in the low resolution case, while in the high resolution case, the performance was more mixed.

\paragraph{Bayes Classifier.}
In comparison, the Bayes classifier performed significantly worse than the SVMs, with test errors ranging from 14.04\% to 18.80\% across folds and resolutions.
The Mahalanobis distance approach yielded higher error rates compared to the SVMs, indicating that the assumptions of Gaussian distributions may not hold well for
this dataset.

\paragraph{Why did the Bayes classifier perform so poorly?}
This initially made me curious about why the Bayes classifier performed so poorly, and compared Mahalanobis distance with the case III classifier; This
comparison is shown in Table \ref{tab:mahalanobis_caseIII}. The case III classifier, which assumes each Gaussian has different shapes and sizes, performed significantly better
than the Mahalanobis distance approach. I suspect that although PCA does de-correlate data across both classes, the within-class covariance matrix may not be well
approximated with a diagonal matrix with the off-diagonal elements set to zero, which is what the Mahalanobis distance approach assumes. This could explain the significant
performance gap between the two methods.

\paragraph{Val/Test Error Gap.}
One interesting observation from the results in Table \ref{tab:val_test_gap} is the significant gap between validation and test errors for some of the SVM configurations, particularly for the
polynomial kernel at low resolution. For example, in fold 2 of the 16x20 resolution, the polynomial kernel achieved a validation error of 4.51\% but a test error
of 9.02\%, which is a substantial increase. This suggests that the model may be overfitting to the validation set, and highlights the importance of using a separate
test set to evaluate the true generalization performance of the model. Similar patterns can be observed in fold 2 of the 48x60 resolution for both polynomial and RBF
kernels, where validation errors were around 3.76\% but test errors jumped to around 9\%.
